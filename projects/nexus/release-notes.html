Release Notes · Console Beta v2.0

What changed since v1.0.

The console first shipped as Beta v1.0. This page is the changelog for Beta v2.0 — each addition with the engineering and architectural reasoning behind it. For the full delivery record and the rollout gate, see the stage catalogue.

Updated 17 August 2026 · baseline green

The console first shipped as Beta v1.0. This wave — built across 15–16 August — is Beta v2.0: twelve engineering and architectural additions, each its own governed sub-project through the same Spec → Plan → Subagent build → Whole-branch review cycle. Items marked In build are on their feature branch and finalise on merge + portfolio sync.

✦
Typology pattern-walks — Shadow Fleet & SpoofingGrounded SAN002 (shadow fleet) and CM003 (spoofing/layering) walks join the Circular-Funds-Flow U-turn — each a real data-driven pattern over the two-tier graph, dispatched by scored typology with no typology branch in the renderer (guardrail 3 held).
Built
✦
Estate entity integrity & governed screeningCodename→canonical rename across every table; a governed SCREENING_MATCH_MIN = 85 threshold applied to all sanctions/PEP derivations; a PEP director resolved onto a customer; and a new pep_connection score that ranks any ownership-network link to a PEP into the alert table.
Built
✦
Knowledge Centre — typology doctrine hubAll 50 typologies across the five crime families curated from their toolkit descriptors into a governed doctrine library + hub + per-typology pages — provenance-cited to the source file, coverage-gated, no fabrication.
Built
✦
Doctrine seam — “Typology Library” in the workspaceThe workspace typology deep-links to its authored doctrine page via a gold Typology Library button. The typology→page resolution is computed server-side and gated on authored coverage — the renderer holds no typology branch, only “link if a URL was baked in.”
Built
✦
Operations layer — supervisor dashboard + navA supervisor read-model over the same case/task spine (queue funnel, band/state, analyst workload, honest SLA, QA sample) as a second surface, reached from an Operations button in the console header. Analyst’s desk and manager’s desk, one substrate.
Built
✦
MI Explorer — the analyst’s pivot tabA Tableau-style second tab on the ops dashboard: aging · jurisdiction · typology overlay views behind one shared filter bar + a CSV extract, over an enriched per-task row-model with a real seeded aging history so the SLA and age profiles are live.
Built
◆
Vessel Lens — the vessel as a first-class nodeThe vessel becomes a graph node (namespaced from the vessels table) with OWNS_VESSEL / SHIPPED_ON / STS_WITH edges and a fourth maritime lens. A shared hull is now a findable path between two otherwise-unconnected customers, and a sanctioned vessel propagates risk along the edge — structural fusion, not a shipping side-console.
Built
◆
Maritime data integrity & TBML011The shipping-data upgrade: deterministic vessel identity-integrity checks (the “zombie-ship” IMO-reuse problem — caught before a clean sanctions screen is trusted), a unit-price fix that makes over-invoicing computable (and retro-strengthens TBML001), and a new typology TBML011 — freight-cost inflation (value displaced into freight/insurance + price-cap circumvention). Pure arithmetic over pillar tables — no AIS feed, no model, no new dependency.
Built
✦
Two-score triage — governed weights, dedupe, and calibration MIThe macro triage score got a breakdown card that shows every contributing signal on the front screen, its weights moved into a governed macro_scoring_config, and a real defect fixed: jurisdiction deviation was double-counting the same corridor. Behind it, a calibration layer (signal_calibration + model_performance_mi) reports firing rate, escalation funnel, false-positive rate and SAR conversion per config version — honestly volume-gated, so it reports no rate on a thin sample. The decision record (ADR-002) states plainly that the 100 cap is a triage flattener, not a limit, and that the weights are uncalibrated v1 pending run history.
Built
✦
AI Copilot — opt-in LLM SAR refinementThe deterministic SAR drafter gained a refinement seam: an opt-in LLM pass that improves narrative prose while the facts stay locked to the provenance-linked draft. Fail-safe by construction — no API key means it is a no-op and the deterministic draft ships unchanged. The governed artefact is never the model's output; the model only rewrites language it is not allowed to invent.
Built
◆
Vessel detail panel — the hull's whole storyClicking a vessel now answers "what physical asset carried this, and who else used it?" in one surface: every shipper on the hull (each row click-navigable, so a shared hull becomes an investigation step), the identity timeline with a contested-vs-churn integrity flag, and dark activity — AIS gaps and ship-to-ship transfers, with a Dark STS chip when a hull goes dark and transfers at the same location. Shown, deliberately not scored: concealment is surfaced as evidence before it is priced into a number.
In build
◆
Brand ignition & console identityThe demo now opens through a governed ignition sequence — the NEXUS shield charging, flashing and releasing a shockwave before the console resolves — and the console header carries the approved metallic shield-and-wordmark lockup as an embedded asset rather than ad-hoc inline markup. One brand definition, reused, not redrawn per surface.
