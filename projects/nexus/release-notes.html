Release Notes · Beta v2.2

What's new in Beta v2.2.

The core build is the investigator console: one resolved-entity substrate fusing transaction monitoring, sanctions and case management, with governed typologies, doctrine and scoring. Beta v2.2 is what has been built on top of it since then, all on synthetic data. The full delivery record, wave by wave, is in the stage catalogue.

Updated 21 October 2026 · Beta v2.2 · 6,619 tests passed, 0 failed, CI-gated

Since Beta v2.2

✦
A telemetry page that shows the workThe telemetry page now leads with today's risk level against the bank's own 20-day normal (learned over its first 20 business days), and one planted scheme told as a short story by role. An activity dashboard shows the case flow by severity, the backlog and today's risk profile by typology. Below it, an engineering section gives system owners the run history, data feeds, drift and any failure, pinned at the top.
Live
✦
A governed data dictionaryThe data dictionary is built from the governed data_dictionary.yaml, 44 tables across 10 pillars. It is checked against the generators' real CSV headers and the ingest table map, so the page, the data and the loader cannot drift apart unnoticed.
Live
◆
A test phase before the next featuresFrom 19 October new features are frozen while the platform is tested. Agents run test packages every night against a fixed baseline: 313 new tests in the first two nights, each one seen to fail before it was trusted. The expected outcomes for the realistic test estate are written from the typology doctrine, never from the code, and signed off typology by typology.
