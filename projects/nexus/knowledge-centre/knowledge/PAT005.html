PAT005 · Network Intelligence

Common Address

Do two or more entities share the same address?

Supporting questions:

How many entities use the address?

Is the address residential or commercial?

Is the address associated with high-risk entities?

Does the address appear in multiple ownership structures?

Does the address indicate a shell company network?

Does the address create additional risk?

NI005 Common Address identifies entities connected through a shared address.

The purpose of this intelligence product is to detect relationships that may indicate:

  • Undisclosed connections
  • Common control
  • Related-party activity
  • Shell company networks
  • Network clustering
  • Beneficial ownership concealment
  • Financial crime exposure

While a shared address alone is not suspicious, it may become highly significant when combined with ownership, control, trade or sanctions indicators.

Risk indicators

Risk

  • Twenty entities registered at same address
  • Address linked to shell companies
  • Address linked to sanctioned entity
  • Address appears across multiple ownership networks
  • High-risk address cluster detected

How this pattern looks

Engine sample · synthetic data

A worked example, step by step: one finding of fc-03's common-address analytic over its own synthetic sample network of 16 entities and 15 relationships, and the records the engine read for it. Every company is fictional. The engine's rule is the address text: it reads each entity's address, trims it and writes it in lower case, and returns a finding for every text that more than one entity gives. This page's description says a shared address alone is not suspicious and may become highly significant when combined with ownership, control, trade or sanctions indicators, and its questions ask whether the address is residential or commercial: the engine does not combine anything and cannot say what kind of address it is, so the ownership records the input holds for these entities are shown and the address rule reads none of them. The engine then scores each finding with a network risk engine; four of the five figures behind that score describe the whole sample network and not the address, and two are zero only because the analytic hands the engine nothing for them, so each step says only whether the engine's output holds a figure above zero. The engine gives no alert line. The subject is the address NEXUS's adapter chose, the one given by the most entities, not a choice the engine makes. This is the engine's own output for one sample address, not a customer case.

Each step: what the engine states, and the rule behind it

  • found the engine's output holds it for the subject
  • not found the engine looked and its output holds none
  • not stated the engine's output does not say, or its figure is zero here

  1. Common address

    found

    What the engine statesThe engine's output holds a common-address finding: the address "unit 4, 12 harbour road, douglas", as the engine writes it, is given by 3 entities: Orion Holdings Ltd (C001), Bluewave Investments Ltd (C002), Redwood Holdings Ltd (C007)

    The ruleCommon address: the engine reads the address column of every entity record, trims it and writes it in lower case, and returns a finding for every text that more than one record gives. Punctuation, the spacing inside the text and the order of its words are kept, so two addresses that differ by a character are two addresses, and a record with no address gives none. It reads no relationship, no country and no entity type, and it does not know what an address is: a serviced office shared by many companies is a finding like any other. The step is found where the engine returned a finding for the subject's address. The subject is always one of the engine's own findings, so this step is found for every finding the walk shows

The engine compares the text after trimming it and writing it in lower case, so the capital letters above are not what it compared

    The ruleEntity risk: the engine reads a risk score from each entity record of the whole network it is given, a record with no such column reading as 0 (a blank value stops the engine), and takes the mean over all entities. The toolkit's entity file for this sample has no risk score column, so every entity reads 0 and this component is 0 whoever the entities are. It describes the whole network and not the subject, and every finding of this sample run carries the same figure. The step is found where the engine's figure is above zero and not stated where it is zero. A zero here means nothing was supplied, not that the entities are clean

  5. Relationship risk

    found

    What the engine statesThe engine's output gives relationship risk 38.69 of 100 for the network, at a weight of 20%, which is 7.738 points of the engine's score for this finding

    The ruleRelationship risk: the engine gives each relationship of the whole network a base figure by its type (ultimate controller 90, control 85, beneficial owner 80, trades with or transacts with 60, director of or shares contact with 55, shares address with 50, sanctions exposure 100, any other type 40; the engine's table spells the two shares kinds SHARES_CONTACT_WITH and SHARES_ADDRESS_WITH, so a record spelled SHARES_CONTACT or SHARES_ADDRESS reads as any other type), multiplies it by that relationship's own confidence and takes the mean over all of them, so many ordinary relationships dilute a severe one. The sample's 15 relationships are all OWNS, a type the engine's table does not list, so each reads as any other type (40), with confidences averaging 0.9673, so this component is 40 times 0.9673, which the engine rounds to two places, 38.69. It reads every relationship of the file and not the finding's own, so every finding of this sample run carries the same figure. A blank confidence value stops the engine, and a missing confidence counts as 1. Every relationship scores at least 40 times its own confidence, so this figure is above zero for any network with a relationship of some confidence: found here says the network has relationships, not that any is severe. The step is found where the engine's figure is above zero and not stated where it is zero

The analytic hands the engine no list of ownership paths, so this component is 0 in every run of this analytic.   7. Exposure risk

    found

    What the engine statesThe engine's output gives exposure risk 10 of 100 for the network, at a weight of 20%, which is 2 points of the engine's score for this finding

    The ruleExposure risk: the analytic hands the engine the finding itself as its one exposure indicator, and the engine reads its text: the finding's own fields (the type, the shared address, the connected entities and their count), written out as Python prints a dictionary, field names included. The row the run keeps is that dictionary plus typology_id, typology_name and risk_assessment, which the analytic added afterwards, so the run holds the fields the text was read from. The engine's rule on that text: it adds 40 if the text contains SANCTION, otherwise 25 if it contains PEP, otherwise 20 if it contains ADVERSE or HIGH RISK, and otherwise 10 (capital letters are ignored, and a name that merely contains those letters counts: a name containing PEP would score 25), then 15 for each connected high-risk entity the network figures report, up to 45, capped at 100. The analytics engine's network figures hold a node count and an edge count and report no connected high-risk entity. The text of this finding contains none of those words, so the engine adds 10 for it. That 10 is what any finding of this kind gets when its text holds none of those words. The step is found where the engine's figure is above zero and not stated where it is zero. A figure here says the engine was handed something to read, not that anything about the subject is exposed

  8. Structural risk

    found

    What the engine statesThe engine's output gives structural risk 52.5 of 100 for the network, at a weight of 10%, which is 5.25 points of the engine's score for this finding

    The ruleStructural risk: the engine adds three points for each node up to 30, one and a half for each relationship up to 30, ten for each level of ownership depth up to 25, and 100 times the network's density up to 15, capped at 100. The analytics engine's network figures hold a node count and an edge count and no network size, ownership depth or density (it also returns lists of components, clusters, bridges, influence and exposure, which the risk engine does not read), so only the first two parts can score. This sample network has 16 nodes and 15 relationships, which the engine reads as 30 for the nodes and 22.5 for the relationships (one and a half times 15), 52.5 in all. It describes the whole network and not the subject, and every finding of this sample run carries it. The first part scores at least 3 for any network with a node, so this figure is above zero for any network with a node: found here says the network has size. The step is found where the engine's figure is above zero and not stated where it is zero. A figure here says the network is that large, not that it is risky

    not found

    What the engine statesThe engine's output names no risk driver for this finding

    The ruleRisk drivers: the engine builds a sorted list of named drivers from the whole network and the finding: Beneficial ownership relationship identified when ANY relationship of the network is of that type, Control relationship identified when any is a control relationship, Sanctions exposure relationship identified when any is of that type, Layered ownership structure when it is handed an ownership path of depth 3 or more (none is here), Large connected network when the network figures give a network size of 10 or more (the analytics engine gives a node count and no network size, so this driver cannot appear for these runs), Connected high-risk entities when the figures count any (none), a Sanctions exposure or PEP exposure indicator when the finding's text contains sanction or pep, and Critical aggregate network risk at a score of 85 or more. The drivers about relationship types describe the whole network, not the subject. The step is found where the engine's list holds a driver and not found where it is empty
