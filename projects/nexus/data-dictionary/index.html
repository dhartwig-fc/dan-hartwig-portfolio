Estate map — tables & connections

The entity_key spine. `entities` is the one resolved-party table; ~13 tables carry entity_key as an anchor (transactions, kyc_profile, ownership, screening, shipping, trade, intel, tasks…). Resolution (SP1–SP3) guarantees one entity_key per real-world party across every source, so a transaction, a sanctions hit, an ownership edge and a case task about the same party all line up without reconciliation.

Reading the keys — key & relationship roles

PKPrimary key — uniquely identifies each row in its own table (one per table, e.g. designation_id, account_id).
FKForeign key — points to another table's primary key, forming the join (e.g. screening_results.designation_id → sanctions_list).
ANCHORentity_key anchor — the special FK that resolves the row back to the one canonical party in entities; the cross-pillar spine.
REFReference link — join into a governed lookup table (country, currency, industry, designation) that is periodically refreshed.
