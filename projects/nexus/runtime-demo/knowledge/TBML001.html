TBML001 · TBML

Over Invoicing

Are import or export transactions being deliberately over-invoiced to facilitate the movement of illicit value across borders?

Over-invoicing is a common Trade-Based Money Laundering technique whereby the price of goods is intentionally inflated beyond their true market value.

The excess value embedded within the invoice enables the covert transfer of funds between counterparties while appearing to represent legitimate trade activity.

Common objectives include:

  • Laundering criminal proceeds
  • Capital flight
  • Tax evasion
  • Sanctions circumvention
  • Hidden value transfer between related parties

How this pattern looks

Engine sample · synthetic data

A worked example, step by step: one invoice of the toolkit's synthetic demonstration case, as the TBML001 engine scored it. Every name is fictional. The engine did not read this case from its own sample files: fc-10's adapter builds the engine's input from the run's case, a governed demonstration case, and hands it the invoice reference, the exporter's name as its customer field, the commodity code, the declared value, the benchmark value and nine more fields of the case. The engine sees no document: it works out one price variance from the two values and reads it with the nine fields, ten values in all. It sets six bands from them and checks no other value against another, or against the route, the dates or the goods description the case also holds. The case labels the two values USD, the engine reads no currency, and the cut-offs below are the engine sample's own thresholds, not any regulator's. A figure the case leaves blank is refused by fc-10's adapter before the engine is called, so a blank figure is never scored: the declared value, the benchmark value, the transaction value and the prior alerts count each raise an error naming the field. This is the engine's own output for one demonstration invoice, not a customer case.

Each step: what the engine states, and the rule behind it

  • found the engine rates it Medium, High or Critical
  • not found the engine rates it Low
  • not stated the engine's output does not hold it

  1. Invoice value against its benchmark

    found

    What the engine statesThe run gives the declared value as 2,500,000 and the benchmark value as 1,700,000, and the engine's price variance as 47.06% (shown to two decimals). The case labels both values USD

    The rulePrice inflation: the engine divides the gap between the invoice's unit price and the benchmark unit price by the benchmark, as a percentage, and matches the invoice to its benchmark by commodity code; an invoice whose commodity code matches no benchmark has no variance and gets no row. In this run fc-10 hands the engine the whole invoice's declared value as the unit price and the whole benchmark value as the benchmark unit price. The engine reads no quantity and no currency. It returns a row only for a variance above 30%, so a band of Low or Medium never reaches a row. A variance of 10% or less is Low; more than 10% up to 30% is Medium; more than 30% up to 60% is High; more than 60% is Critical. These are the engine sample's own thresholds, not any regulator's. Engine band: High. This component carries 30% of the score: 21 points

  2. Trade value

    found

    What the engine statesThe run's case gives the transaction value as 2,500,000, which fc-10 hands the engine. The case labels it USD

    The ruleTrade value: the engine reads the transaction value, which fc-10 reads from the run's case and hands the engine. Its scorer names the figure as US dollars, and no currency enters a score. A value under 50,000 is Low; 50,000 to under 250,000 is Medium; 250,000 to under 1,000,000 is High; 1,000,000 or more is Critical. These are the engine sample's own thresholds, not any regulator's. Engine band: Critical. This component carries 15% of the score: 13.5 points

  3. Corridor and sanctions flags

    found

    What the engine statesThe run's case gives the high risk corridor flag as true and the sanctions exposure flag as false, which fc-10 hands the engine

    The ruleJurisdiction: the engine reads a high-risk corridor flag and a sanctions exposure flag, which fc-10 reads from the run's case and hands the engine. A true sanctions flag is Critical; otherwise a true corridor flag is High; otherwise Low. The engine's scorer has no Medium for this component. The engine sees no country or route, only the flags. Engine band: High. This component carries 15% of the score: 10.5 points

  4. Counterparty risk band

    found

    What the engine statesThe run's case gives the counterparty risk band as High and the adverse media flag as false, which fc-10 hands the engine

    The ruleCounterparty: the engine reads a counterparty risk band label and an adverse media flag, which fc-10 reads from the run's case and hands the engine. A true adverse media flag is Critical; otherwise a label of Critical, High or Medium (ignoring capitals and surrounding spaces) gives that band; any other label gives Low, including a label the engine does not know, which is not refused. The label is one the case gives, and the engine does not check it against anything. Engine band: High. This component carries 15% of the score: 10.5 points

  5. Shell and shared-control flags

    found

    What the engine statesThe run's case gives the shell company indicator as true, the shared director flag as true and the shared owner flag as true, which fc-10 hands the engine

    The ruleNetwork: the engine reads a shell company indicator, a shared director flag and a shared owner flag, which fc-10 reads from the run's case and hands the engine. A true shell indicator is Critical, and the director and owner flags then change nothing; otherwise a true director or owner flag is High; otherwise Low. The engine's scorer can take a common address, which would give Medium, but the engine never passes one, so this case cannot give Medium. Engine band: Critical. This component carries 15% of the score: 13.5 points

    The ruleHistorical behaviour: the engine reads a prior alerts count, which fc-10 reads from the run's case and hands the engine. A count of 0 is Low; 1 is Medium; 2 or more is High. The scorer can also take a SAR history flag, which would be Critical, but the engine never passes one. Engine band: Low. This component carries 10% of the score: 1.5 points

    not stated
